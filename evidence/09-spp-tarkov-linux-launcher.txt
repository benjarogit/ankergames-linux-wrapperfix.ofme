# SPP Tarkov (3089) — native launcher instead of WebView2 under Wine

Same prefix, Proton Experimental (wine-11.0), native server on
`https://127.0.0.1:6969`.

The Windows launcher is Photino/Blazor on WebView2. Under Wine its page is a D3D
swapchain in a child window owned by `msedgewebview2.exe`, which does not
present here — the window stays white. WebView2 also sets the cursor from the
browser process, and Wine cannot map that handle to an X11 cursor (Wine bug
58922), so the pointer is invisible. The package ships the same launcher as a
native Linux build; that one renders with GTK/WebKit.

## 1 · Play starts the native launcher

`Play` calls `umu-run Launcher.exe`. The corrected wrapper checks for the
native launcher next to that executable. It starts the server if needed
and then launches the native client (see sections 6 and 7):

```
SPP Tarkov: starting the native SPT launcher
Photino.NET: "SPT Launcher".SetIconFile(/tmp/SPT.Launcher/spt-logo.ico)
```

The launcher window is `SPT Launcher - Server: Local Se…`, the Local Server card
is ONLINE (`assets/spp-tarkov-launcher-linux.png`).

## 2 · Launcher config

`SPT_Runtime/user/Launcher/LauncherSettings.json` — the values the script writes:

```json
"GamePath": "/mnt/daten/Games/AnkerGames/Games/Prefixes/3089/drive_c/Games/SPP-Tarkov",
"LinuxSettings": {
  "PrefixPath": "/mnt/daten/Games/AnkerGames/Games/Prefixes/3089",
  "UmuPath": "/usr/bin/umu-run",
  "ProtonVersion": "/home/benny/.local/share/Steam/steamapps/common/Proton - Experimental",
  "GameMode": false,
  "DefaultEnv": "WINEDLLOVERRIDES=\"winhttp=n,b\""
}
```

`UmuPath` must be the Python script (`/usr/bin/umu-run`), not the shell wrapper:
the launcher runs `python3 <UmuPath> <cmd>` itself. With a missing path, **START
GAME** fails silently and the launcher shows `Game Failed to start:`.

## 5 · Why the WebView2 flags do not help

`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-gpu` (environment variable and
the `HKCU\Software\Policies\Microsoft\Edge\WebView2` policy) had no visible
effect on the white window or the cursor. Photino passes its own
`AdditionalBrowserArguments` when it creates the WebView2 environment, and
WebView2 ignores the external arguments once the app supplies its own. Forcing
`PROTON_USE_WINED3D=1` makes the Windows launcher paint, but the game inherits
it and loses DXVK.

## 6 · Play uses "umu-<n>", not "3089" as GAMEID

The first wrapper block keyed on `GAMEID=3089`. A real Play click from Anker
Launcher 0.1.30 passes a per-game umu id instead:

```
$ tr '\0' '\n' < /proc/<umu-run pid>/environ | grep '^GAMEID='
GAMEID=umu-3932890
```

The block therefore did not trigger, and the Windows launcher
(`S:\Games\AnkerGames\Games\Escape from Tarkov-3089\SPT_Runtime\SPT.Launcher.exe`)
started under Proton — the white window titled *SPP Tarkov - Servers*.

The block now keys on the file, not the id: if `SPT_Runtime/SPT.Launcher.Linux`
sits next to the `Launcher.exe` that umu-run was called with, the native
launcher starts. Test with the same environment and working directory the
launcher uses:

```
$ GAMEID=umu-3932890 WINEPREFIX=…/Prefixes/3089 PROTONPATH=…/Proton\ -\ Experimental \
    ~/.local/bin/umu-run "$PWD/Launcher.exe"
SPP Tarkov: starting the native SPT launcher
Photino.NET: "SPT Launcher".SetIconFile(/tmp/SPT.Launcher/spt-logo.ico)
```

A window titled *SPT Launcher* opens and renders the page ("Lade…"), so the
native path no longer depends on the id AnkerGames chooses.

## 7 · Clean Play test after the fix (2026-11-26)

Anker Launcher 0.1.30, KDE Wayland, umu-launcher 1.4.3 and Proton Experimental.
The AppImage was started with APPIMAGE_EXTRACT_AND_RUN=1 because FUSE mounting
was unavailable in the test environment. No GTK backend override was set.

13:26:19 CET — One Play click on Launcher.exe. No SPT launcher, SPT server or
Tarkov process was running before the click. Exactly one SPT.Launcher.Linux
and one SPT.Server.Linux started. The native SPT Launcher - Servers window
rendered and displayed Local Server as ONLINE.
https://127.0.0.1:6969/launcher/v2/ping returned HTTP 200.

13:28:00 CET — One START GAME click after selecting the local profile.
AnkerGames' game log recorded "Running 'Proton - Experimental'". The
EscapeFromTarkov.exe process reached Choose Your Faction, with in-game
FIKA 2.4.2 and SPT 4.1.2 labels. Server log excerpts:

```
[Client Request] /fika/client/check/version
[Client Request] /client/game/start
[Client Request] /client/game/profile/list
```

The stop script closed the game, its Wine session and the native launcher.
The server still returned HTTP 200. A second invocation with --server closed
the server and left no TCP listener on port 6969.

Forcing GDK_BACKEND=x11 in an earlier attempt on this Wayland session also
started exactly one native launcher and server, but the launcher window was
blank. The two processes were closed before the clean Wayland test.
